# 03 · Aritmética IEEE 754 en TranSim754

Este documento resume la parte de IEEE 754-2019 que implementa el proyecto y la ilustra
con seis ejemplos resueltos a mano, bit a bit. Los seis resultados se verifican de
forma automática contra numpy en `tests/docs/test_ejemplos_ieee754.py`.

## 1. Formatos

Un número de punto flotante binario se codifica en tres campos:

```
 ┌───┬──────────────┬─────────────────────────┐
 │ s │ E (e bits)   │ f (f bits)              │
 └───┴──────────────┴─────────────────────────┘
```

| Parámetro | binary32 (oficial) | binary16 (pruebas y demos) |
|---|---|---|
| Bits de exponente e | 8 | 5 |
| Bits de fracción f | 23 | 10 |
| Precisión p = f + 1 | 24 | 11 |
| Sesgo = 2^(e−1) − 1 | 127 | 15 |
| emin = 1 − sesgo | −126 | −14 |
| emax = sesgo | 127 | 15 |
| Mayor finito | (2 − 2^−23) · 2^127 ≈ 3.4028235 · 10^38 | 65504 |
| Menor normal | 2^−126 ≈ 1.1754944 · 10^−38 | 2^−14 ≈ 6.1035 · 10^−5 |
| Menor subnormal | 2^−149 ≈ 1.4012985 · 10^−45 | 2^−24 ≈ 5.9605 · 10^−8 |

En el código todo se deriva de `FloatFormat(exp_bits, frac_bits)` (ADR-0001).

## 2. Clases de valores

| Clase | E | f | Valor |
|---|---|---|---|
| Cero | 0 | 0 | (−1)^s · 0 |
| Subnormal | 0 | ≠ 0 | (−1)^s · 0.f · 2^emin |
| Normal | 1 … 2^e − 2 | cualquiera | (−1)^s · 1.f · 2^(E − sesgo) |
| Infinito | 2^e − 1 | 0 | (−1)^s · ∞ |
| NaN | 2^e − 1 | ≠ 0 | NaN; quiet si f₍MSB₎ = 1, signaling si f₍MSB₎ = 0 |

El **bit implícito** vale 1 en los normales y 0 en los subnormales y los ceros. En el
hardware, cada operando se "desempaqueta" a `(signo, exponente sin sesgo, mantisa de
p bits con el bit implícito explícito, clase)`. Para un subnormal, el exponente sin
sesgo es emin (no emin − 1), lo que garantiza la continuidad entre subnormales y
normales.

**NaN canónico** del proyecto: signo 0, E todo unos, f = `10…0` → binary32
`0x7FC00000`, binary16 `0x7E00` (ADR-0003).

## 3. Redondeo roundTiesToEven

Tras calcular el resultado exacto (o una representación suficiente de él), la mantisa
tiene más bits de los que caben. Se conservan p bits y se resumen los demás en:

```
  1 . b1 b2 … b(p−1) │ G │ R │ S
  └──── se conserva ─┘   │   └ OR de todos los bits siguientes
                         └ round
```

Regla (ADR-0002): **incrementar = G · (R + S + LSB)**; **inexacto = G + R + S**.

| G R S | Lo descartado vale | Acción |
|---|---|---|
| 0 0 0 | 0 | exacto |
| 0 x x (≠ 000) | menos de ½ ulp | truncar, inexacto |
| 1 0 0 | exactamente ½ ulp | empate: incrementar solo si LSB = 1 |
| 1 1 x ó 1 x 1 | más de ½ ulp | incrementar, inexacto |

## 4. Flags

| Flag | Condición (manejo por defecto, IEEE 754-2019 §7) |
|---|---|
| invalid (NV) | ∞ − ∞, 0 × ∞, 0/0, ∞/∞, o algún operando sNaN |
| divideByZero (DZ) | x / 0 con x finito ≠ 0 |
| overflow (OF) | el resultado redondeado con exponente ilimitado supera el mayor finito; el resultado es ±∞ y también se levanta inexact |
| underflow (UF) | el resultado es diminuto **después** de redondear (magnitud < 2^emin) **y** es inexacto |
| inexact (NX) | el resultado entregado difiere del exacto |

Los flags son acumulativos en el FSR (ADR-0004).

## 5. Ejemplos resueltos (binary32)

Notación: los bits se agrupan de a cuatro para leerlos en hexadecimal; `│` separa los
campos s │ E │ f.

### Ejemplo 1 · Codificar −6.25

1. Signo: negativo → s = 1.
2. Magnitud en binario: 6.25 = 4 + 2 + 0.25 = 110.01₂.
3. Normalizar: 110.01₂ = 1.1001₂ × 2². Exponente sin sesgo 2.
4. Exponente almacenado: E = 2 + 127 = 129 = 1000 0001₂.
5. Fracción: los bits después del punto, completados a 23: `1001 0000 0000 0000 0000 000`.

```
1 │ 1000 0001 │ 1001 0000 0000 0000 0000 000
= 1100 0000 1100 1000 0000 0000 0000 0000 = 0xC0C80000
```

### Ejemplo 2 · FADD 1.5 + 2.25 = 3.75 (exacto)

| Operando | Binario | Normalizado | E | Bits |
|---|---|---|---|---|
| a = 1.5 | 1.1₂ | 1.1₂ × 2⁰ | 127 | `0x3FC00000` |
| b = 2.25 | 10.01₂ | 1.001₂ × 2¹ | 128 | `0x40100000` |

1. **Comparar exponentes:** E_b − E_a = 1 → b es el mayor; el resultado toma E = 128.
2. **Alinear:** se desplaza la mantisa de a una posición a la derecha:
   1.1000…0 → 0.1100…0; el bit que sale es 0 → G = R = S = 0.
3. **Sumar mantisas** (signos iguales → suma efectiva):
   ```
     1.0010 0000 …   (b)
   + 0.1100 0000 …   (a alineado)
   = 1.1110 0000 …
   ```
4. **Normalizar:** ya tiene la forma 1.xxx; no hay desplazamiento.
5. **Redondear:** GRS = 000 → exacto.
6. **Empaquetar:** s = 0, E = 128 = 1000 0000₂, f = `1110 0000 …`.

```
0 │ 1000 0000 │ 1110 0000 0000 0000 0000 000 = 0x40700000 = 3.75     flags: ninguno
```

### Ejemplo 3 · Empates a par: 2^24 + 1 y (2^24 + 2) + 1

En [2^24, 2^25) el ulp vale 2, así que los enteros impares no son representables.

**(a)** a = 2^24 = `0x4B800000` (E = 151), b = 1.0 = `0x3F800000` (E = 127).

1. Diferencia de exponentes: 151 − 127 = 24.
2. Alinear b 24 posiciones a la derecha: su 1 implícito queda justo una posición a la
   derecha del LSB de a → **G = 1, R = 0, S = 0**.
3. Suma de mantisas: 1.000…000 + 0 en las posiciones conservadas → LSB = 0.
4. Redondeo: G = 1, R = S = 0 es un **empate**; LSB = 0 (par) → **no se incrementa**.

Resultado: `0x4B800000` = 16 777 216 (el exacto era 16 777 217). Flags: inexact.

**(b)** a = 2^24 + 2 = `0x4B800001` (fracción `000…001`, LSB = 1), b = 1.0.

Mismo procedimiento: G = 1, R = S = 0 (empate), pero ahora LSB = 1 (impar) →
**se incrementa**: fracción `000…010`.

Resultado: `0x4B800002` = 16 777 220 (el exacto era 16 777 219). Flags: inexact.

Ambos casos muestran que en un empate se elige el vecino con LSB par, sea hacia abajo
o hacia arriba.

### Ejemplo 4 · FMUL con resultado subnormal: `0x00800001` × 0.5

| Operando | Bits | Valor |
|---|---|---|
| a | `0 │ 0000 0001 │ 000…001` | 1.000…01₂ × 2^−126 = 2^−126 + 2^−149 |
| b = 0.5 | `0 │ 0111 1110 │ 000…000` = `0x3F000000` | 1.0₂ × 2^−1 |

1. **Signo:** 0 ⊕ 0 = 0.
2. **Exponente:** −126 + (−1) = −127.
3. **Mantisas:** 1.000…01 × 1.0 = 1.000…01 (exacto; 23 ceros y luego un 1).
4. **Normalizar:** el producto ya está en [1, 2).
5. **Detección de resultado diminuto:** el exponente −127 es menor que emin = −126.
   Se desplaza la mantisa emin − e = 1 posición a la derecha para expresarla con
   exponente −126:
   ```
   1.0000 0000 0000 0000 0000 001  × 2^−127
   0.1000 0000 0000 0000 0000 000 │ 1  × 2^−126
                                     └ G = 1, R = 0, S = 0
   ```
6. **Redondear:** empate (G = 1, R = S = 0) con LSB = 0 → no se incrementa.
7. **Empaquetar:** subnormal → E = 0, f = `100 0000 0000 0000 0000 0000`.

```
0 │ 0000 0000 │ 1000 0000 0000 0000 0000 000 = 0x00400000 = 2^−127
```

8. **Flags:** el resultado redondeado con exponente ilimitado (2^−127 · (1 + 2^−23))
   es menor que 2^−126 → diminuto; además G = 1 → inexacto. Se levantan
   **underflow** e **inexact**. El valor exacto 2^−127 + 2^−150 se perdió por
   exactamente medio ulp de subnormal (2^−150).

### Ejemplo 5 · FDIV 1 / 3 con guard, round y sticky

| Operando | Bits | Normalizado |
|---|---|---|
| a = 1.0 | `0x3F800000` | 1.0₂ × 2⁰ |
| b = 3.0 | `0x40400000` | 1.1₂ × 2¹ |

1. **Signo:** 0. **Exponente:** 0 − 1 = −1.
2. **Mantisas:** 1.0₂ / 1.1₂ = 1 / 1.5 = 0.101010…₂ (periódico).
3. **Normalizar:** el cociente es menor que 1 → se desplaza una posición a la izquierda
   y el exponente pasa a −2: 1.0101 0101…₂ × 2^−2. Por eso el divisor genera un bit
   más de cociente (ADR-0009).
4. Se generan p + 2 = 26 bits de cociente:
   ```
   1.0101 0101 0101 0101 0101 010 │ 1 │ 0 │ resto ≠ 0
                                    G   R   S = 1
   ```
5. **Redondear:** G = 1 y S = 1 → más de medio ulp → se incrementa:
   fracción `0101 0101 0101 0101 0101 010` + 1 = `0101 0101 0101 0101 0101 011`.
6. **Empaquetar:** E = −2 + 127 = 125 = 0111 1101₂.

```
0 │ 0111 1101 │ 0101 0101 0101 0101 0101 011
= 0011 1110 1010 1010 1010 1010 1010 1011 = 0x3EAAAAAB ≈ 0.33333334
```

Flags: inexact. El error es +1/(3 · 2^25) ≈ 9.9 · 10^−9, menor que medio ulp (2^−26).

### Ejemplo 6 · Overflow: mayor finito × 2

| Operando | Bits | Valor |
|---|---|---|
| a | `0x7F7FFFFF` | (2 − 2^−23) × 2^127 |
| b = 2.0 | `0x40000000` | 1.0₂ × 2¹ |

1. **Exponente:** 127 + 1 = 128 > emax = 127.
2. **Mantisa:** 1.111…1₂ × 1.0₂ = 1.111…1₂ (exacto, GRS = 000).
3. El valor exacto (2 − 2^−23) × 2^128 supera el mayor finito: **overflow**. En
   roundTiesToEven el resultado es ±∞ con el signo del resultado exacto.

```
0 │ 1111 1111 │ 0000 0000 0000 0000 0000 000 = 0x7F800000 = +∞
```

Flags: **overflow** e **inexact**.

## 6. Tablas de casos especiales

Notación: `F` = finito distinto de cero; `qN` = NaN quiet; `sN` = NaN signaling;
`NaNc` = NaN canónico. Si algún operando es NaN, el resultado es NaNc (con NV solo si
alguno es sNaN), y esa regla tiene prioridad sobre las tablas.

**Suma x + y** (la resta x − y se trata como x + (−y)):

| x \ y | +0 | −0 | F | +∞ | −∞ |
|---|---|---|---|---|---|
| +0 | +0 | +0 | y | +∞ | −∞ |
| −0 | +0 | −0 | y | +∞ | −∞ |
| F | x | x | x + y (si x = −y: +0) | +∞ | −∞ |
| +∞ | +∞ | +∞ | +∞ | +∞ | NaNc, NV |
| −∞ | −∞ | −∞ | −∞ | NaNc, NV | −∞ |

**Multiplicación x × y** (signo = s_x ⊕ s_y):

| x \ y | 0 | F | ∞ |
|---|---|---|---|
| 0 | ±0 | ±0 | NaNc, NV |
| F | ±0 | redondeo(x · y) | ±∞ |
| ∞ | NaNc, NV | ±∞ | ±∞ |

**División x / y** (signo = s_x ⊕ s_y):

| x \ y | 0 | F | ∞ |
|---|---|---|---|
| 0 | NaNc, NV | ±0 | ±0 |
| F | ±∞, DZ | redondeo(x / y) | ±0 |
| ∞ | ±∞ | ±∞ | NaNc, NV |
